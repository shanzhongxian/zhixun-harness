# 智训引擎 · 使用说明与内容文档

> 训练师模型（Qwen3.8-27B）作为决策层，分析数据漂移/过拟合并调度工业模型续训；
> 工业模型（CPU NumPy MLP）完成三项真实任务；harness 负责诊断、门禁与版本管理。
>
> ⚠️ 已重组：源码在 `../src/`，请从**包根目录**用 `python src/...` 运行；快速上手见 [README](../README.md)。

---

## 1. 项目概述

本项目是「智训引擎赛道」的第一版实现。核心是让一个**训练师模型（Qwen3.8-27B）**根据观测报告自主决策，驱动**工业模型**针对三个工况做续训与适配。系统闭环为：

```
诊断（观测层） → 决策（训练师/规则） → 训练（续训） → 门禁（accepted/rejected） → 版本管理
```

三个工况（训练包）：

| 工况 | 任务 | 分组键（漂移单元） | 主指标 | 随包基线 → 续训后（公开验证集） |
|---|---|---|---|---|
| A 气体识别 | 6 类分类 | `meta.source_batch` | Macro-F1（越大越好） | 0.7140 → 0.7187 |
| B 轴承 RUL | 回归（分钟） | `meta.bearing` | RMSE（越小越好） | 681.16 → 662.79 |
| C 发动机 RUL | 回归（循环） | `meta.source_subset` + `meta.unit` | RMSE（越小越好） | 52.87 → 51.88 |

## 3. 快速开始（使用说明）

### 3.1 环境要求

- Python 3.10+（本机 3.13.5 已验证）
- `numpy`（工业模型必需）
- `pytrio`（**仅** `--strategy qwen` 时需要；缺省/规则/模拟策略不需要）

在仓库根目录下运行。

### 3.2 命令

**⓪ 平台握手（T02，不训练）**

```bash
python src/scripts/handshake.py --mock --profile A --batches 3 --clean
python src/scripts/handshake.py --real --profile A --batch-dir inbox --submit-dir submit
```

**⓪′ PyTRiO 探测（T05，默认不训练）**

```bash
python src/train_pytrio.py --probe            # 只检查凭据与模型
python src/train_pytrio.py --probe --generate # 加一次 ≤32 token 推理
```

**① 自测（验证代码与三条路径）**

```bash
python src/selftest.py
```

**② 三项工况，规则决策（第一版默认）**

```bash
python src/harness.py --profile all --strategy rule
```

**③ 单任务，模拟训练师（联调用，确定性、不联网）**

```bash
python src/harness.py --profile A --strategy mock --epochs 5
```

**④ 真实训练师（Qwen3.8-27B，PyTRiO）**

```bash
python src/harness.py --profile A --strategy qwen --model-id Qwen/Qwen3.8-27B
```

> Qwen 调用失败/超时/解析失败时，harness 自动降级到规则决策，不会中断。

**⑤ 质检：记录完整性 + 回滚演练**

```bash
python src/scripts/check_records.py
python src/scripts/drill_rollback.py
```

**⑥ 绘图（需 matplotlib，按工况输出到 plots/）**

```bash
python src/scripts/plot_results.py
```

### 3.3 命令行参数（harness.py）

| 参数 | 默认 | 说明 |
|---|---|---|
| `--profile` | `A` | `A` / `B` / `C` / `all` |
| `--strategy` | `rule` | `rule`（规则）/ `mock`（模拟训练师）/ `qwen`（真训练师） |
| `--epochs` | `5` | 决策建议的续训轮数（1–200） |
| `--lr-scale` | 按任务 | 学习率倍率；缺省 A=0.3、B=0.5、C=0.3（0.01–1.0） |
| `--patience` | `2` | 早停：验证主指标连续几轮不超过父检查点就停 |
| `--batch-size` | 沿用检查点 | 批大小（1–65536） |
| `--rounds` | `1` | 连续执行多少轮决策 |
| `--min-improvement` | `1e-6` | 门禁最小改善量（低于此视为未改善） |
| `--output-dir` | `runs/rounds` | 候选检查点输出目录 |
| `--model-id` | `Qwen/Qwen3.8-27B` | 训练师模型 ID（`--strategy qwen` 用） |

### 3.4 隔离运行（测试/多实例）

设置环境变量 `HARNESS_RUNS_DIR` 可把版本指针与决策日志放到独立目录，避免污染正式 `runs/`：

```bash
# Windows PowerShell
$env:HARNESS_RUNS_DIR='.test\runs'
python src/harness.py --profile A --strategy rule --output-dir .test/rounds
```

## 4. 核心概念（内容说明）

### 4.1 三层结构

```
训练师（Qwen3.8-27B）──决策(JSON)──▶ harness ──训练──▶ 工业模型（MLP，续训）
        ▲                                    │
        └────────观测报告(JSON 文本)──────────┘
```

训练师是个 LLM，只能“看见”文本。观测层把模型状态翻译成命名、数字化的事实喂给它；
它输出结构化决策，由 harness 校验、执行、并回传 before/after 结果形成闭环。

### 4.2 可调旋钮 schema（训练师能输出什么）

训练师只能输出 schema 里声明的键，越界会被夹到边界、未知键会被拒绝。

**第 1 版已接线（tier 1）：**

| 旋钮 | 类型 | 范围 | 默认 |
|---|---|---|---|
| `lr_scale` | float | 0.01–1.0 | 按任务 |
| `epochs` | int | 1–200 | 5 |
| `batch_size` | int | 1–65536 | 沿用检查点 |
| `patience` | int | 1–100 | 2 |
| `weight_decay` | float | 0–1e-3 | 0 |

**已声明、尚未接线（tier 2，保留接口）：** `dropout`、`label_smoothing`、`class_weight`。

### 4.3 决策对象格式

训练师输出的 JSON（由 harness 校验）：

```json
{
  "action": "train | no_op | rollback",
  "hypothesis": "一句话说明原因（非空，供审计）",
  "evidence_ids": ["gap", "drift_flag", "group_metrics"],
  "params": {"lr_scale": 0.3, "epochs": 5, "patience": 2}
}
```

- `action`：`train` 续训 / `no_op` 不动 / `rollback` 回退上一版本。
- `hypothesis` + `evidence_ids`：SwanLab 加分与可审计性的来源。
- 非法决策（非法 action、空 hypothesis、越界参数）→ 自动降级为 `no_op`，来源记为 `fallback`。

### 4.4 观测报告字段（喂给训练师）

```json
{
  "primary_metric": "macro_f1", "direction": 1,
  "train_loss": 0.135, "validation_loss": 0.521, "gap": 0.385,
  "train_metrics": {...}, "validation_metrics": {...},
  "group_metrics": [{"group": [2], "primary": 0.714, "n": 1244}],
  "n_groups": 1, "overfit_flag": false, "drift_flag": false
}
```

- `gap` = 验证损失 − 训练损失（越大越像过拟合）。
- `overfit_flag` / `drift_flag`：预计算好的启发式信号（第一版阈值，需校准）。
- `group_metrics`：按真实分组（批次/轴承/发动机）的主指标，用于发现“最差组”与漂移。

### 4.5 门禁与版本管理

- 候选在**完整公开验证集**上与当前版本比主指标，`direction*(候选-当前) > min_improvement`，且**回放集（留出的未见工况组）不退化**，两者同时满足才 `accepted`，否则 `rejected`。
- `accepted` 时更新版本指针（旧版本存入 `previous`，支持 `rollback`）。
- 决策日志与版本指针落盘：

| 产物 | 路径 | 内容 |
|---|---|---|
| 版本指针 | `runs/current.json` | 每工况的 `checkpoint` / `previous` / `best_metric` / `rounds` |
| 决策日志 | `runs/decisions.jsonl` | 每轮完整诊断 + 决策 + 结果（供 SwanLab/审计关联） |
| 候选 | `runs/rounds/round-N/<profile>/` | `checkpoint.npz` + `training.json` + `history.jsonl` |

### 4.6 三条关键路径

1. **候选通过（accepted）**：续训后验证主指标改善 → 更新版本指针。
2. **候选退化（rejected）**：续训后验证主指标变差 → 保留当前版本，只记录日志。
3. **非法决策降级（fallback）**：决策格式/参数非法 → 降级 `no_op`，不执行危险动作。

三条路径均有自测覆盖（`python src/selftest.py`）。

## 5. 三个工况的差异化策略

| 工况 | 主要矛盾 | 规则层触发 | 后续重点 |
|---|---|---|---|
| A 气体识别 | 批次漂移 + 样本极少（445 行） | 单批次验证，`drift_flag` 恒为 false | 漂移鲁棒标准化、dropout、类别权重 |
| B 轴承 RUL | 欠拟合 + 缺时间趋势 | 3 组轴承 RMSE 差异大 → `drift_flag` 触发 | 时间窗特征、Huber 损失 |
| C 发动机 RUL | 数据多、NASA 非对称评分 | 多台发动机 RMSE 差异大 → `drift_flag` 触发 | 时间窗、NASA 评分作第二门禁 |

## 6. 已知限制与后续计划

1. **早停集与门禁集未分离**：目前都用 `public/validation.jsonl`，反复调参会对公开验证集元过拟合；需按组拆出独立的早停集与门禁集。
2. **阈值是占位**：`overfit_flag`/`drift_flag` 的阈值需用历史数据校准（例：A 训练 F1 0.956 vs 验证 0.714 明显过拟合，但 gap 0.385 未触发 overfit_flag）。
3. **部分正则未接线**：`weight_decay`（L2）已接线；`dropout`/`label_smoothing`/`class_weight` 仍只是声明。
4. **特征工程未做**：B/C 的时间窗、A 的漂移鲁棒标准化是最大提升空间（需换特征 schema 或权重迁移）。
5. **模型 ID 需核对**：`Qwen/Qwen3.8-27B` 按约定拼写，平台注册表实际 ID 若有差异请用 `--model-id` 覆盖。
6. **平台协议**：批次握手、产物格式、no-op、鉴权与超时见 [平台协议](平台协议.md)（T01/T02 已落地 adapter 与握手脚本）。

**建议实施顺序**：三分离验证集 → 阈值校准 → tier-2 正则化接线 → 特征工程 → 真 Qwen 联调。

## 8. SwanLab 分组约定

每轮训练在 SwanLab 建一个 run（`<数据集>-round<轮次>`），并按数据类型归组，便于同组并排比较：

| 数据集 | 工况 | SwanLab group |
| --- | --- | --- |
| A | 气体识别（分类，macro_f1） | `Gas` |
| B | 轴承 RUL（回归，rmse/mae） | `Bearing` |
| C | 涡扇发动机 RUL（回归，rmse/mae） | `Turbofan` |

实现位置 `src/runtime/swanlab_log.py`（`DATASET_GROUPS`），run 的 config 里同时写入 `dataset_group` 字段。
SwanLab 页面上每个组即是一个数据类型，组内是该工况的历轮实验。
